- (decision) AD-1 [ADOPTED]: Single-package Go module — the entire service lives in one package (internal/) under the module root. Two independent agents building this would both pick a single package; splitting into handler/service/infrastructure layers is over-engineering for a hello world and would cause incompatible code organization.
- (decision) AD-2 [ADOPTED]: HTTP server uses net/http with explicit Server struct, ListenAndServe, and Shutdown — standard library only. No third-party HTTP frameworks. Two agents would both reach for net/http for a hello world; introducing chi or gin would be a divergence with no benefit.
- (decision) AD-3: Health endpoint returns JSON {"status":"ok","message":"Hello, World!"} with Content-Type: application/json. The PRD specifies this exact shape at FR-1.
- (decision) AD-4 [ADOPTED]: PORT env var defaults to 8080, read via os.Getenv("PORT") with strconv.Atoi validation. Two agents building independently would both choose this pattern — it's the standard Go idiom.
- (decision) AD-5 [ADOPTED]: Graceful shutdown via context.Context with os/signal handling for SIGINT/SIGTERM, calling server.Shutdown(ctx) with a 5-second timeout. This is the standard Go pattern and two agents would converge on it.
- (decision) AD-6 [NEW]: Server timeouts — http.Server must have ReadTimeout=5s, WriteTimeout=10s, IdleTimeout=30s to prevent slowloris and ensure consistent agent behavior.
- (decision) AD-7 [NEW]: Makefile targets — build=go build ./..., test=go test -race -v ./..., run=go run .
- (decision) AD-8 [NEW]: Test scenarios — tests must cover: (1) 200 with correct JSON body, (2) Content-Type header, (3) 405 for non-GET methods.
